# 未·央 · 双人叙事解谜 Demo

> 两个人看到的长安，未必是同一座城。你的选择，也会改变搭档能走的路。

**《未·央》**是一款架空盛唐背景的真人双人联机叙事解谜游戏原型。两位玩家分别扮演**大理寺巡捕**与**年轻幻术师**，从东市追镜时的初遇出发，穿过八起案件，在万象台作出最后的选择。

![未·央的长安与曲江地图](assets/map-ground.png)

**固定角色 · 私人线索 · 双向选项联动 · 环绕调查 · 协作 QTE · 共同存档 · 五种结局**

当前仓库包含从引子到结局的**完整主线紧凑 Demo**。章节经过压缩，尚不是原企划中 6–8 小时的正式游戏；演出、平衡和操作手感仍可继续打磨。

## 版本与试玩

- **本仓库：**完整篇代码、原创场景及人物素材、房间服务、玩法文档与测试。
- **[此前公开试玩](https://changan-moon-himon2000.kl564203.chatgpt.site/)：**较早部署的版本。此次 Git 更新不包含上线部署，网站内容可能与仓库不同。
- **运行最新版：**按下方步骤启动本地房间服务，与同一网络的搭档游玩。无需注册账号或安装额外游戏客户端。

## 快速开始

### 1. 启动房间服务

先安装 **Node.js 18 或更新版本**。如需构建云端版本或运行全部测试，建议使用 Node.js 24。

```sh
git clone https://github.com/himon2000/weiyang-demo.git
cd weiyang-demo
node server.cjs
```

打开 **http://localhost:8787/**，并保持启动服务的终端窗口运行。

也可使用项目内启动器：

- **macOS：**双击 `启动联机.command`。
- **Windows：**双击 `启动联机.bat`。
- **Linux / 通用方式：**在项目目录运行 `node server.cjs` 或 `npm start`。

本地服务只用 Node.js 内置模块，**直接运行不需要先执行 `npm install`**。

> 真人联机需要房间服务。仅双击 `index.html`，或仅将静态文件放到 GitHub Pages，无法提供双人房间。

### 2. 两位玩家加入同一个房间

1. 房主选择「巡捕」或「幻术师」，点击「创建双人房间」。
2. 在等待页面复制邀请链接，发给搭档。
3. 搭档打开链接，选择另一个身份，点击「加入搭档」。邀请链接会预填房间码，也可以手动输入。
4. 两人到齐后，分别进入各自的引子。身份选定后全程固定。

**本地联机时，两台设备需在同一局域网。** 搭档使用等待页面显示的局域网邀请地址；`localhost` 只指向正在使用的那台电脑，不能作为发给另一台电脑的地址。跨网络的无下载试玩需另行部署云端房间服务。

想在一台电脑上体验两条线，可新开两个独立标签页：一个创建房间，另一个从首页加入。不要复制已登录房间的标签页来充当另一位玩家。

默认端口为 `8787`。如果已被占用，可以设置 `PORT`；例如 macOS / Linux：

```sh
PORT=8791 node server.cjs
```

## 详细玩法

### 两个角色，各自掌握一部分事实

| 角色 | 主要行动 | 独立信息 |
| --- | --- | --- |
| **巡捕** | 查痕迹、核证词、追捕、保护现场 | 人的行动时间、伤痕、文书、生活与使用痕迹 |
| **幻术师** | 查光路、拆机关、辨幻影、调整装置 | 镜片角度、牵线、配重、水道、声学与幻术异常 |

两人可以按自己的速度阅读。分头行动时，每人只能看到自己取得的调查记录。建议开语音或坐在一起交流：**说清楚你看见什么，再比较搭档的发现。**

### 基本操作

| 界面 | 操作 |
| --- | --- |
| 世界地图 | 将鼠标移到建筑或船只上；轮廓会浮起并发光，点击进入。地图不常驻显示地点名字。 |
| 剧情对话 | 点击右下角「续」继续。选项在画面中间出现；由当前发言角色的玩家决定。 |
| 场景调查 | 按住鼠标左右拖动环视，也可用底部滑条或左右按钮。直接点击可疑物件，名称不会提前标出。 |
| 线索记录 | 点击命中物件范围即可收集。重复查看不会重复获得数值奖励；已取得的内容可在「案卷」中回看。 |
| 双人验证 | 各自提交自己掌握的证据或验证步骤。两端信息吻合才继续，答错可核对后重试。 |
| QTE | 双方先点击准备，再按提示的 **W / A / D**，或点击动作按钮。 |
| 共同存档 | 点击顶部「存档」，选择节点发起读档，等搭档同意后一起返回。 |

### 每案如何推进

1. **到达现场：**查看地图左上角的简短任务提示，进入对应建筑。
2. **分头调查：**环视场景、点取物件、完成各自问询。新增章节通常要求双方各取得至少两项现场记录，并完成私人问询。
3. **会合交流：**两人到齐后进入共同剧情。搭档的选择可能为你打开或关闭一条行动路线。
4. **验证机关：**将两份独立记录对应起来。曲江需要各交一条证物；其他章节各提交自己的验证步骤。
5. **共同指认：**分别提交判断，意见一致后结案。证据不足时可以保留疑点，不必强行选出完整推理。
6. **更鼓确认：**双方确认这一夜的经历，进入下一章，并留下章节共同存档。

### 选择怎样影响搭档

- 巡捕是否放倒东市绸架，会改变幻术师追上屋顶的路线。
- 巡捕是否委托机关调查，会影响幻术师能否进一步分享验证方法。
- 幻术师是否先分享船舱结构图，会影响巡捕的追问与配重救援选项。
- 断桥追逐中，幻术师先决定引光还是系绳，巡捕再选择对应路线。
- 西市舞台上，幻术师先揭镜或灭灯，巡捕获得不同的追捕、守门与保护选项。
- 低信任可能使异常记录暂不分享；隐瞒与坦诚会继续影响后续剧情。

无法使用的选项会显示**缺少的前置行动或数值条件**，不会替另一位玩家自动作决定。

### QTE 与机关

全篇包含东市屋顶、船底灌水、断桥追逐三段双人 QTE。每段各有三步动作，**双方各成功至少两步**才算共同成功；失误仍能继续故事，但可能改变证据、失稳或后续描述。

- 巡捕与幻术师的提示键和动作各自独立，要看自己屏幕上的提示。
- QTE 开始后，切换标签页或打开设置不会暂停计时。
- 可在开始前于「设置」中开启舒缓模式，延长自己的动作时间。
- 大明宫可以亲手移动碎片、留下记号、等待更鼓，再检查复原结果。
- 死人授业案中，巡捕排列画像残片，幻术师以自己的物证核对；残片支持拖动，也支持依次点击。

## 数值、隐藏剧情与结局

数字默认不直接展示；在设置中可开启调试数值。关键选项选定后会提示实际变化。

| 数值 | 初始值 | 影响 |
| --- | ---: | --- |
| 巡捕对幻术师的信任 | 50 | 是否相信搭档的指引、能否采用某些合作行动 |
| 幻术师对巡捕的信任 | 50 | 是否分享异常记录、是否愿意暴露自己的记忆 |
| 真相认知 | 5 | 异常细节、隐藏记录与结局条件 |
| 幻境依恋 | 65 | 对维持长安的倾向与部分结局条件 |
| 幻境失稳 | 0 | 破坏和失误造成的后果、提前进入终章的风险 |
| 证据完整度 | 每案 0 | 当前案件精准推理的开放条件，上限 10 |

前五项范围为 0–100；两种信任分别计算，不是一个共同好感值。关键剧情通常还需要具体物证或前置事件，不能只靠数值开启。

例如：证据完整度不足时，完整推理会锁定；达到真相条件后，倒影与战争旧痕会更明显。达到相应信任条件后，搭档才愿意主动交出异常记录。

## 自动存档、共同读档与断线重连

- 房间服务在有效操作后自动保存进度；本地存放在 `.rooms/`，不会上传到 Git 仓库。
- 重要双人选项前、各章节开启和最终选择前，会生成可回退的共同存档。
- 读档由一人发起，另一人确认。读档会同时恢复双方的剧情、数值和线索；身份保持原样。
- QTE 进行中需先完成当前动作段，再发起读档。
- 原标签页刷新会尝试恢复身份和进度；连接中断时会自动重连。请保留自己的标签页。
- 身份凭证保存在标签页会话中。清除会话或主动离开后，不能仅用房间码接管已占用的身份，可新建房间重新开始。
- 本地服务重启会恢复最近七天内保存的房间；关闭服务期间两人都会断线。

### 常见问题

**一直显示「等另一人」？** 先确认搭档已经加入同一房间，然后让搭档完成当前阅读、选择、调查或准备。共同节点要求双方各自完成，不能只由一个人连续点击推进。

**无法会合或某个选项是灰色？** 查看任务提示、两人的案卷和选项下方的条件。新增章节需各自调查和问询；完成一人的部分不能代替另一人。

**搭档打不开本地邀请？** 确认两台设备在同一网络、房主服务仍在运行，并使用局域网地址。`localhost` 地址不能发给另一台电脑使用。

**公开试玩里没有仓库的新内容？** 代码推送与网站部署是两件事。当前公开试玩保留较早版本，完整篇以本仓库为准。

## 开发、构建与验证

### 本地测试

```sh
npm test
```

当前包含 **16 项测试**：从独立引子到真结局的双人通关、无需改数值的低信任结局路线、五种结局条件、私有线索与角色权限、错误验证重试、重复奖励防护、跨章节读档、高失稳提前终章、曲江 QTE 成功/失败分支、页面模板及 HTTP/SSE 重连。

这些自动验证不替代两台设备上的完整人工试玩。

### 云端构建（不会自动发布）

使用 Node.js 24，在项目目录执行：

```sh
npm ci
npm run build
npm run test:cloud
```

构建产物位于 `dist/`：前端图片转为 WebP，云端房间使用 Worker / D1 保存状态，通过版本条件更新和请求去重处理双方同时操作。云端测试验证房间持久化、认证轮询、并发和重试去重。运行构建命令不会上传或部署网站。

项目也保留本地 Node 服务与 Dockerfile。Node 服务采用单进程房间状态；经公网代理使用时需支持 SSE、关闭流缓冲并提供 HTTPS。
